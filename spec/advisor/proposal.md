# Proposal: Financial Advisor Skill

## Problem

Бот накопил данные о тратах, доходах, повторяющихся платежах, долгах и прогнозе, но пока приносит профит только как трекер — пользователь видит цифры, а не решение. Семья экспатов (доход RUB, траты THB) регулярно сталкивается с вопросами «можем ли мы это купить сейчас?», «есть ли более приоритетные траты?», «сколько свободных денег до зарплаты?» — и вынуждена считать сама. Нужно, чтобы бот отвечал на такие вопросы автоматически, используя весь доступный финансовый контекст.

## Users

| Role | Current pain | Change |
|------|-------------|--------|
| Владелец бюджета (taras) | Считает сам, держит в голове все обязательства, прогноз, долги | Задаёт вопрос — получает вердикт с цифрами |
| Партнёр (жена) | Те же данные, тот же чат, должен видеть один ответ для обоих | Один ответ для обоих, общий бюджет |

## Solution

Добавить advisor skill в Go-сервис simpleAI. Skill автоматически вызывается LLM-роутером при детекте финансового вопроса (не отдельная команда). Skill собирает финансовый снэпшот одним SQL-запросом, передаёт LLM вместе с вопросом и возвращает гибридный ответ: короткий вердикт + 2–3 ключевые цифры. Развёрнутый разбор — по follow-up запросу. Все суммы в THB (как в forecast skill).

## Scope

**In scope:**
- Новый Go skill `advisor` в `internal/skill/` (или аналогичный путь по проекту)
- Auto-routing через манифест (LLM сама понимает «это финансовый вопрос»)
- Финансовый снэпшот одним SQL: текущий остаток месяца, расходы по категориям, прогноз до конца месяца, активные повторяющиеся платежи, открытые долги
- Все суммы конвертированы в THB
- Гибридный ответ: вердикт `Да/Нет/Условно` + 2–3 цифры; следующая итерация по follow-up
- Stateless: каждый запрос обрабатывается независимо

**Out of scope:**
- RAG / база знаний с книгами по финсоветам (отдельный итерация, связан с #43)
- Мультивалютный вывод (RUB и THB раздельно)
- Многошаговый agent loop с вызовом других skill'ов как tools
- Команда `/advice` (явный триггер) — только автороутинг
- Совместная история разговора (context memory)

## User Flow

```
User: "можем купить велосипед за 25000 THB?"
  ↓
agent.Service → LLM router → advisor skill (по manifest match)
  ↓
advisor.Run():
  1. SELECT финансовый снэпшот (один SQL CTE):
     - balance_month_to_date THB
     - spent_by_category MTD THB
     - forecast_remaining_month THB
     - upcoming_recurring (до конца месяца)
     - active_debts (сумма + дедлайн)
  2. Передать снэпшот + question в LLM
  3. LLM возвращает: verdict + key_numbers + short_reasoning
  ↓
Bot: "Да, можем. Свободно ~18k THB после обязательств. Прогноз до зп: −12k. Спросить детали?"
  ↓
User (опц.): "детали"
  ↓
advisor вызывается повторно с тем же снэпшотом → расширенный разбор
```

## Tech Context

- **Stack:** Go 1.25, PostgreSQL, slog, agent.Service + plugin.Registry, DeepSeek (primary) / Gemini (fallback)
- **Key entities:**
  - `budget_transactions` (расходы/доходы по категориям, валюта)
  - `budget_recurring` (повторяющиеся платежи)
  - `budget_debt` (открытые долги — проверить точное имя таблицы)
  - `exchange_rate` (текущий курс валют, **только текущий** — историч. курсов нет, см. issue #46)
  - `CategoryForecast` (forecast skill: avg + trend по CTE)
- **Existing mechanisms to reuse:**
  - Manifest-based routing skill'ов (как в `budget_skill.go`)
  - `agent.ChatIDKey{}` для chatID из контекста
  - SQL CTE pattern из `GetForecastData()` для snapshot
  - Структурные slog-логи (skill, input, duration_ms)
- **Constraints:**
  - Stateless agent — никакого conversation history
  - Все skill'ы манифестируются с описанием для LLM
  - Multi-user chat (taras + жена) — один общий бюджет, chatID идентифицирует чат
