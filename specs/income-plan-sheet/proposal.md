# Proposal: Общий план прихода (таблица + бот как два интерфейса одной логики)

## ГЛАВНОЕ (приоритет №0, слова владельца)
Без видимого экрана (UI или таблица Excel) вся затея бессмысленна. Экран обязан показывать **все ячейки по всем категориям с суммами, а при необходимости — детали** (какие именно траты в сумме). Бот и логика вторичны: они кормят этот экран. Сначала делается экран, всё остальное строится вокруг него.

## Problem
Когда приходит зарплата (20-го, ~130 000 ₽), нет одного окна, где видно: сколько на каждую категорию, сколько на долги, сколько отложить и сколько ещё можно потратить. Деньги утекают на мелочи (кофе, такси, рынок), долги не закрываются, общей картины нет. Telegram для обзора не годится. Боль ежемесячная, острая из-за кредитов.

## Users
| Role | Current pain | Change |
|------|-------------|--------|
| Владелец | Не знает, сколько куда; в Telegram нет единого взгляда | Вносит доходы и расходы как в обычном Excel, видит план, остаток и историю |
| Партнёр / семья | Не видит картину | Работает с той же таблицей, имеет общий доступ; траты может вносить и через Telegram (бонус) |
| Бухгалтер / помощник | Нечем проверить цифры | Смотрит сводные итоги и долги в общем доступе |
| Бот simpleAI | Единственный интерфейс — чат | Остаётся удобным способом быстро внести трату на ходу, пишет в тот же слой данных |

Ролей и прав доступа нет: все, у кого есть ссылка, видят и правят одинаково.

## Solution
Один слой данных и логики (она уже реализована в боте: конверты ADR-008, safe-to-spend), два тонких интерфейса: общая таблица и Telegram-бот. Таблица считается сама: вносишь число в графу «доход» — сразу пересчитывается всё. Логика расчёта не зависит от интерфейса и дорабатывается только при необходимости. Отдельного триггера «20-го» нет: план живой и всегда актуален.

## Scope
**In scope (целиком, без урезанного MVP — сводная таблица либо есть, либо её нет):**
- План на приход: сколько на каждую категорию, сколько на долги, сколько отложить
- История трат по месяцам (ретроспектива, включая мелочи)
- Текущий остаток и перерасход («сколько ещё можно потратить»)
- Долги и срок закрытия
- Чистка категорий: слить дубли («Еда» / «продукты» / «продукт»), структура категория + подкатегория (кофе, туалетная бумага, такси, пакет на рынке видны отдельно)
- Общий доступ нескольким людям; бот вносит траты в тот же слой

**Out of scope (потом):**
- Роли и права доступа
- Прогноз на будущие месяцы (план только на текущий период)
- Графики и дашборды (только таблица с числами)
- Отдельная двусторонняя синхронизация как механизм (см. открытый вопрос 1)

## User Flow
```
1. Владелец (или партнёр) вносит доход в таблицу ИЛИ расход в таблицу / боту
2. Данные попадают в общий слой; формулы пересчитывают план
3. В таблице видно сразу: на каждую категорию, на долги, отложить, сколько ещё можно
4. Ошибку в записи можно поправить в таблице, сводка покажет исправленное
5. Бот по запросу даёт ту же сводку в чате
Триггера и напоминаний не требуется: план обновляется при любом вводе.
```

## Tech Context
- Stack: Go, PostgreSQL (+pgvector), Telegram-бот, MCP; прод — один сервер, деплой через GitHub Actions
- Key entities: `budget_transaction`, `budget_category` (39 шт., есть дубли), `budget_debt` (пуста), `budget_recurring` (аренда 18 000 ฿ 10-го, Сбер 28 500 ₽ 27-го, подписка 1 700 ₽, платёж 3 000 ₽ 1-го), `budget_envelope*`, курс THB
- Existing mechanisms to reuse: раскладка по конвертам (ADR-008), safe-to-spend (ADR-007), ручной курс бата, ежедневный дайджест
- Принцип: интерфейсы тонкие, логика одна (KISS, SRP). Формат таблицы (Google Таблица / Excel в облаке / веб-страница) выбирает архитектор по простоте
