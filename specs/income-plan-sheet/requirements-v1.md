# Requirements: Общий план прихода

Источник: proposal.md. Шаг SDD 00 выполнен без вопросов владельцу (его инструкция: после интервью шаги идут без него). Неясное закрыто разумным значением по умолчанию и помечено **[допущение]**.

## Анализ proposal

**Неоднозначности**
- «Таблица или UI» — формат не выбран → решает constraints.md (допущение A1).
- «Правки руками в таблице» против «двусторонняя синхронизация — потом» → снимается выбором формата: если экран работает прямо с базой, синхронизации нет (A1, A2).
- «Период» плана не определён → допущение A3.

**Недостающая информация**
- Остатки и проценты по долгам (таблица долгов пуста).
- Назначение платежа 3 000 ₽ и актуальность кредитной карты.
- Желаемая валюта показа.

**Неявные допущения**
- Источник трат — существующие `budget_transaction`; ничего не вводится заново.
- Курс бата берётся как в боте (ручной курс перекрывает автоматический).
- Доступ по секретной ссылке считается достаточной защитой (ролей нет).

**Граничные случаи**
- Трата без категории; трата в USD/EUR; приход дважды в месяц; перерасход больше лимита; пустой период; два человека правят одну запись одновременно; удалённая категория.

**Допущения по умолчанию (владелец может изменить)**
- A1. Основной интерфейс — веб-страница, которую отдаёт сам бот-сервис (таблица в браузере, с телефона и компьютера) + кнопка «Скачать Excel». Google Таблица откладывается.
- A2. Источник правды — база. У экрана нет собственной копии данных.
- A3. Период плана — от даты последнего прихода до даты следующего ожидаемого (по умолчанию 20→20, то есть с 20-го по 19-е следующего месяца); границы можно сдвинуть вручную.
- A4. Валюта показа по умолчанию ₽, переключатель на ฿ (как у конвертов бота).
- A6. Лимит ставится на уровне категории; у подкатегории показываются «потрачено» и «в день», своего лимита нет.
- A5. Долги вносятся владельцем; до этого блок долгов показывает пустое состояние с подсказкой, а не нули.

## Функциональные требования

### Экран (приоритет №0)
- R1. Одна страница показывает таблицу «категория × суммы». Для каждой категории и подкатегории видны ячейки: лимит на период, потрачено, осталось, в день.
- R2. Видны ВСЕ категории, включая мелкие (кофе, туалетная бумага, такси, пакет на рынке). Скрытых и «свёрнутых навсегда» категорий нет. Категории без трат тоже видны.
- R3. Подкатегории сворачиваются/разворачиваются внутри категории; сумма категории = сумма её подкатегорий.
- R4. Клик по ячейке «потрачено» раскрывает детали: список трат (дата, сумма, валюта, описание, кто внёс).
- R5. Блоки экрана сверху вниз: Приход периода → Обязательные платежи → Категории расходов → Долги → Отложить → Итог «ещё можно потратить».
- R6. Итоговая строка показывает: приход, всего запланировано, потрачено, свободный остаток, перерасход красным.
- R7. Вкладка «История»: те же категории по месяцам (ретроспектива), клик по месяцу раскрывает траты.
- R8. Кнопка «Скачать Excel» отдаёт тот же набор данных в xlsx с формулами сумм.

### Расчёт плана
- R9. Приход вносится числом (на экране или боту); при изменении все лимиты пересчитываются без ручного действия. Логика раскладки — существующая (ADR-007, ADR-008), не вторая копия.
- R10. «Отложить» — отдельная строка, значение задаёт владелец. Вычитается из свободной суммы ДО раскладки по категориям (ADR-007/008, constraints C32).
- R11. Блок «Долги» показывает долги из таблицы долгов (остаток, платёж, срок закрытия). Всё, что не распределено по категориям, резерву и платежам, показывается отдельной строкой «Нераспределено» (не подгоняется под приход).
- R12. Чем больше приход, тем пропорционально больше лимиты; логика не зависит от величины суммы.

### Данные и ввод
- R13. Траты вносятся через экран и через бота, оба пишут в одни и те же записи.
- R14. Запись можно исправить или удалить на экране; изменение сразу отражается в боте.
- R15. Категории: слитые дубли («Еда»/«продукты»/«продукт» → одна), структура категория → подкатегория, миграция старых трат в новые категории без потери сумм.
- R16. Долги: ввод остатка, платежа, процента; расчёт срока закрытия (месяцев до нуля).

### Доступ
- R17. Доступ по секретной ссылке; ролей и прав нет — все видят и правят одинаково.
- R18. Кто внёс запись, виден в деталях (имя или идентификатор пользователя).

## Нефункциональные требования
- R19. Открытие страницы ≤ 2 с на текущем объёме (≈500 записей).
- R20. Экран читаем на телефоне (ширина 375 px) без горизонтального скролла таблицы категорий.
- R21. Нагрузка на базу — только чтение для просмотра, запись только при вводе.
- R22. Изменений в текущих расчётах бота (конверты, safe-to-spend) нет, кроме явно перечисленных.

## Вне области (из proposal)
Роли и права, прогноз на будущие месяцы, графики и дашборды, отдельный механизм двусторонней синхронизации.
