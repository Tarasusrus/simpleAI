# Фото чека → расход: требования

Источник: issue #76, решения — [ADR-010](../../docs/adr/010-receipt-photo-vision.md), эпик simpleAI-7mc6.

## Сценарий

Пользователь присылает фото чека → бот проверяет файл → проверяет, что это чек → разбирает →
показывает разбор с кнопками «Записать / Отмена» → по «Записать» создаёт расход.

## Инварианты

| # | Требование | Проверка |
|---|---|---|
| I1 | Картинку получает только модель с vision. Fallback только внутри маршрута `vision` прокси, без перехода на DeepSeek/Gemini | тест vision-адаптера: ошибка → нет второго вызова |
| I2 | Шаги строго по порядку: файл → классификатор → разбор → черновик → подтверждение. Следующий — только после успеха предыдущего | шпион на порядок вызовов |
| I3 | Тип файла — только по сигнатуре; MIME и имя от клиента игнорируются | ZIP с MIME image/jpeg отклонён |
| I4 | Допустимые форматы = возможности группы vision ∩ сигнатуры, которые бот распознаёт. Пусто → отказ до вызова модели | тест на пустое пересечение |
| I5 | Лимит размера — по реально прочитанным байтам | файл больше лимита отклонён |
| I6 | Не чек → ни разбора, ни черновика, ни расхода; пользователь видит причину | шпион на Parser/DraftStore |
| I7 | Черновик только при is_receipt, сумме > 0 и ISO-валюте; без валюты — отказ, не RUB | тест парсера |
| I8 | Расход только по нажатию; Take атомарен; черновик привязан к чату; по TTL истекает с сообщением | двойное нажатие → один расход |
| I9 | Запись через budget skill (`add_expense`) — предупреждение ADR-008 сохраняется | ответ содержит предупреждение |
| I10 | Фото не хранится: ни диск, ни черновик, ни логи; base64 и распознанный текст не логируются | перехват лога; MediaDir пуст |
| I11 | Подпись к фото игнорируется | тест хендлера |
| I11a | В пайплайн идут фото и документы; документ с нераспознанной сигнатурой — старым путём | тест хендлера |
| I12 | Нет `VISION_*` или прокси недоступен → бот стартует, на фото: «обработка фото не настроена»; каталог перечитывается по TTL | тест каталога и хендлера |
| I13 | Текст, голос, аудио, прочие документы работают как раньше | регрессионный тест |
| I14 | Vision-вызовы и нажатия — только для разрешённых чатов (пустой allowlist = все, как сейчас в `RequireAllowedChats`) | middleware разрешённых чатов |

## Вне рамок

- Смена моделей и прод-конфига (`deploy.yml`, `.env`) — решение оператора.
- Защита от повторной отправки того же чека (`file_unique_id`).
- Отдельная работа под PDF: PDF-чек проходит, если группа `vision` умеет `supports_pdf_input`.
