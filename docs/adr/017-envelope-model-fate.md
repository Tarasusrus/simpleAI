# ADR-017: Модель конвертов (ADR-008) устаревает, данные не мигрируются

- **Статус:** Proposed (решение владельца принято 2026-10-23; ждёт ревью и принятия вместе с ADR-016)
- **Дата:** 2026-10-23
- **Задача:** simpleAI-k12g (часть 2)
- **Зависит от:** ADR-016 (бот читает и пишет лимиты через `plan.Service`).
- **Связи:** ADR-008 (конверты-доли), ADR-011 (лимиты плана), ADR-013 §5 (перенос «Еды»).

## Контекст

После ADR-016 бот не использует `budget_envelope_share*` для остатков и лимитов. Оставалось решить, что делать
с самой моделью конвертов: автораскладка прихода по долям (`start_envelope`), виды долей (`spend`, `save`,
`fixed`), перенос остатка (`carried_in`), ручные правки (`budget_envelope_limit_override`), таблицы.

Решение владельца (2026-10-23): **конвертами бота не пользуется, пусть устаревают.** Это снимает необратимую
миграцию данных долей в лимиты, правила маппинга и вопросы про «копилку» (`kind='save'`) и группу категорий.

## Решение

### 1. Конверты устаревают, без миграции данных
- Данные `budget_envelope*` не переносятся в `plan_category_limit` и не изменяются. История остаётся как архив.
- Миграции схемы, правка и удаление таблиц **не входят** в этот ADR. Удаление — отдельным решением, только после
  периода без регрессий и отдельным релизом (если вообще понадобится).

### 2. Что перестаёт работать
- Действие `start_envelope` («пришло X, разложи по конвертам») снимается из Manifest budget-скилла и из
  `ROUTING RULES`; фраза маршрутизируется как обычный вопрос про план/лимиты (ответ даёт ADR-016).
- `set_share_limit` переходит на `plan.Service` (ADR-016 §6) и перестаёт писать
  `budget_envelope_limit_override`.
- Остатки и «на день» из долей (`computeShareRemaining`, `DailyLimit` по долям) заменены чтением плана
  (ADR-016); старый код остаётся за флагом `BOT_LIMITS_FROM_PLAN` на переходный период и удаляется вместе с
  белым списком архитектурного теста (ADR-016 §7).
- Утренний пуш, возивший раскладку конвертов (`internal/envelopepush`), читает план, а не конверты.

### 3. Что остаётся
- Таблицы и данные конвертов в базе (чтение для аудита), код хранения в `internal/budget` до отдельной чистки.
- Раздел ADR-008 «Поправка» (формат ответа, `parse_mode=HTML`) продолжает действовать: он про формат сообщений,
  не про модель конвертов.

### 4. Золотой набор и evals
Кейсы `r043`–`r047` (ADR-008) пересматриваются: «разложи по конвертам» — новый ожидаемый маршрут; «на еду хватит
15000» остаётся `set_share_limit`, но исполняется через план; «сколько в конвертах» — чтение плана. Правка идёт
до кода (ADR-008: сценарии фиксируются до реализации).

## Отвергнуто
- **Миграция долей в лимиты.** Не нужна: конверты не используются; риск изменить «Свободно» без пользы.
- **Копилка (`kind='save'`, `carried_in`).** Владельцу не нужна; перенос остатка плана не поддерживается.
- **Немедленное удаление таблиц.** Необратимо и ничего не даёт сейчас.

## Последствия
+ Нет необратимой миграции; весь риск в обратимом переключении чтения (ADR-016).
+ Один источник лимитов; снимается двойной перенос «Еда» → «Продукты» для долей (ADR-013 §5 по долям
  становится неактуальным после выкатки ADR-016).
− Функции конвертов (автораскладка, перенос остатка) исчезают для пользователя бота. Это решение владельца.
− Старые таблицы остаются мёртвым грузом до отдельной чистки.

## Декомпозиция (после принятия ADR-016)
1. Снять `start_envelope` из Manifest и `ROUTING RULES`, обновить golden-set `r043`–`r047`.
2. Утренний пуш читает план (`envelopepush`).
3. Удалить старый путь за флагом и белый список архитектурного теста — после периода без регрессий.
4. (Отдельным решением, по желанию) чистка таблиц конвертов.
