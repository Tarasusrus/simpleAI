# ADR-018: Страница «Транзакции»: правка и удаление любых транзакций

- **Статус:** Proposed (решение владельца принято 2026-10-26)
- **Дата:** 2026-10-26
- **Задача:** simpleAI-grla (эпик), simpleAI-8f2o (этот ADR)
- **Связи:** ADR-009 §8 (транзакции без `chat_id`), ADR-010 (слияние категорий, мягкое удаление отвергнуто),
  ADR-011 (лимиты плана, предпросмотр), ADR-013 (разделение «Еды»), simpleAI-1inl (правка фактов экрана),
  спека `specs/income-plan-sheet`, R15, issue #82.

## Контекст

Бот иногда записывает трату не в ту категорию («ужин» в «Продукты», «шлем» в «Переводы»). Исправить это руками
нельзя: экран плана правит только факты, которые создал сам (`FactWebLoose`, `FactSettled`, `added_by=web`);
транзакции бота (`FactExternal`) намеренно не трогает, валюта у факта заблокирована (`ErrCurrencyLocked`),
категория игнорируется. Транзакции видны только в деталях категории и в «Истории» (R15), без редактирования.

Решение владельца: править **все** транзакции и **все** поля, на отдельной странице, с журналом изменений
для будущего обучения.

## Решение

### 1. Что можно править
Категорию, сумму, валюту, дату, описание у любой транзакции, включая записанные ботом. Запрет simpleAI-1inl на
правку `FactExternal` и блокировка валюты снимаются. Правка и удаление устроены **одинаково для любой транзакции**, независимо от того, кто её создал (бот, экран,
«оплачено» по плану, правило повтора): один путь, без веток по типу. Единственное ограничение — «Еда» (источник
разделения, ADR-013) не выбирается новой категорией; смена категории идёт через `categories.Resolver`, а не
прямой записью имени.

### 2. Журнал `tx_edit_log`
Каждая правка и удаление пишется в таблицу `tx_edit_log` (id, `tx_id`, действие `edit|delete`, снимок строки до,
значения после, время, источник) **в той же транзакции БД**, что и сама правка. Это источник для будущего
обучения классификатора: сейчас по нему ничего не учим.

Одиночные правки **никогда** не пишутся в `category_merge_log` и split-журнал: откат слияния проверяет «строка
менялась после слияния» и откажет.

### 3. Удаление
Один путь для всех транзакций: жёсткий `DELETE` и запись `delete` со снимком строки в `tx_edit_log` (журнал
удалений = тот же журнал). Мягкое удаление отвергнуто (ADR-010): каждый запрос обязан помнить фильтр.
Восстановление — командой `cmd` из журнала, не из интерфейса.

Особого потока для оплат по плану нет: связь «оплачено» хранится в самой транзакции (`planned_id`, миграция
00023), статус плановой записи выводится из неё (`planrepo/reader.go`). Удалили транзакцию — плановая запись
открыта сама, `UnsettlePlanned` для этого не нужен. Так же для фактов правил повтора: ветки по типу нет; если
воркер повторов пересоздаёт удалённый факт по `(recurring_id, scheduled_for)`, это решается в воркере (он
уважает запись `delete` в журнале), а не особым запретом в удалении. Проверка воркера входит в simpleAI-dvtx.

### 4. Смена валюты
Курс в `budget_transaction` не хранится, THB-вклад считается по текущему `exchange_rate` при показе, поэтому
смена валюты при той же сумме молча меняет исторический вклад. Правило: при смене валюты **новая сумма
обязательна** (автоконвертации нет); форма показывает предпросмотр «было X THB, станет Y THB» по текущему
курсу (как `limits/preview`, ADR-011) и требует явного подтверждения; в журнал пишутся валюта и сумма до и
после. Курс на дату траты в строке — отдельное решение, здесь не принимается.

### 5. Параллельная запись
`PATCH` и `DELETE` несут версию (`updated_at`); устаревшая версия даёт конфликт и ничего не меняет. Это защита
от гонки с ботом, воркером повторов и двойного клика.

### 6. Страница и ссылки
Отдельная страница «Транзакции» (не вкладка «Истории», которая остаётся матрицей категории × месяцы, #82):
список, ручной просмотр и поиск, форма правки. Адрес `/transactions?focus=<id>`: страница открывается на
транзакции, прокручивает её в центр, подсвечивает и сразу открывает форму правки; несуществующий или удалённый
id показывает сообщение, а не пустой экран. С главной, из деталей категории и из «Истории» ведут кнопки
«изменить» / «найти в транзакциях» на эту ссылку, через один общий компонент.

### 7. Область чатов
У `budget_transaction` нет `chat_id` (ADR-009 §8): транзакции общие, как и сейчас. Защиты от «чужого чата»
нет и без миграции быть не может.

## Последствия
- Память `MostUsedCategory` считает по `budget_transaction`, поэтому исправленная строка перестаёт голосовать
  за старую категорию: это **неявное обучение**, принято как следствие. Если старых ошибок бота больше, чем
  правок, бот их повторит; вес ручной правки решается отдельно по журналу.
- «Свободно» и лимиты пересчитываются от новой категории и даты (в том числе при переходе через границу окна);
  нужен тест «до/после».
- Размер: миграция (`tx_edit_log`, `updated_at`), ядро `plan.Service`, BFF, страница, ссылка, кнопки: задачи
  simpleAI-93la … simpleAI-v6cj.

## Не входит
Курс на дату траты в строке; обучение памяти и классификатора по журналу; массовая правка по описанию;
восстановление удалённого из интерфейса.
