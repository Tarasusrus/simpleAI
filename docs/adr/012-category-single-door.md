# ADR-012: Категории — единая дверь для бота и веба, классификатор по списку из БД

- **Статус:** Accepted (подтверждено владельцем 2026-10-21)
- **Дата:** 2026-10-21
- **Контекст эпика:** simpleAI-lsx5 (задача simpleAI-ayec), вердикт architect: YES
- **Дополняет:** ADR-010 §2 (единая точка создания). **Закрывает:** пометку «классификатор не входит» в эпике simpleAI-nebf.
- **Поправляет:** ADR-011 (пример «еда, кафе», см. §8).
- **Зависит от:** ADR-013 (таксономия еды). Список категорий и их определения берутся оттуда.

## Контекст

Бот записал «643 рубля поход в кафе» в «Еда». Причина не в ошибке, а в устройстве:

- Категорию при вводе выбирает LLM по **хардкод-списку из 10 имён** в описании поля `category`
  схемы `add_expense` (`internal/skills/budget/skill.go`, около строки 83). Новая категория в БД
  в схему не попадает, «Рестораны» модель выбрать не может.
- Дедупликатор (`internal/categories/dedup.go`, `DefaultSynonyms`) не классификатор: он сливает
  уже существующие дубли по карте. Карта сама отправляет «ресторан» и «кафе / ресторан» в «Еда».
- Бот идёт через `Resolver` с алиасами (ADR-010 §2). Веб-план резолвит категорию по
  `LOWER(name)` без алиасов и при промахе **тихо пишет NULL**
  (`plan_store.go` AddPlanItem, `plan_edit_store.go` keepCategorySQL, `plan_limit_store.go`
  AddPlanLimit). Одно и то же слово бот и веб трактуют по-разному.

Цель владельца: бот и веб трактуют расход одинаково, модуль категорий один (ADR-010 §2).

## Решение

### 1. Одна дверь
Все интерфейсы (бот, веб-план, повторяющиеся платежи, будущие) получают `category_id` только из
`internal/categories`. Два входа:

- `Resolve(name, type)`: нормализация → алиас → поиск. **Не создаёт.** Результат: категория или
  `ErrUnknownCategory`.
- `GetOrCreate(name, type)`: как сейчас (ADR-010 §2), для бота и повторяющихся платежей.

Прямой SQL по `budget_category` по имени вне пакета запрещён. Три веб-места переходят на
`Resolve`. **Промах больше не пишет NULL:** веб возвращает ошибку «категория не найдена» с
подсказкой существующих. Осознанная строгость: тихий NULL выводит трату из лимитов и прогноза
(ADR-011), и владелец об этом не узнаёт. Веб новых категорий не создаёт (решение по умолчанию;
создание из веба — отдельное решение владельца).

### 2. Откуда берётся список категорий
Одна правда: `budget_category` + алиасы (`budget_category_alias`). Схема `add_expense` строит перечень
категорий из БД в момент сборки инструмента (задача simpleAI-dr42), а не из строки в коде.
Определения категорий (одна строка на категорию, ADR-013) хранятся рядом с категорией и идут
в подсказку классификатору. Хардкод-список в `skill.go` удаляется; тест проверяет, что схема
меняется при добавлении категории в БД.

### 3. Классификатор: когда вызывается
- **Пользователь назвал категорию** («500 на такси, транспорт») → имя принимается как есть, через
  `GetOrCreate` с алиасами, без классификатора (решение владельца).
- **Категория не названа** («643 поход в кафе») → классификатор.
- Слово «еда» без уточнения в описании трактуется по правилу ADR-013 (по умолчанию «Продукты»).

### 4. Классификатор: контракт
Порт `Classifier` в `internal/categories`: на вход описание траты и список кандидатов
(имя + определение), на выход одно имя из списка либо `NONE` с предложением новой категории
(`category_proposal`, очередь `category_review_queue`). Ответ ограничен `json_schema` с `enum`
из имён кандидатов: модель технически не может вернуть имя вне списка.
Адаптер ходит в тот же платный DeepSeek, что чат (`api.deepseek.com/v1`, `deepseek-v4-flash`; изменено 2026-10-22: бесплатные маршруты прокси не тянули по квотам, а DeepSeek не принимает `json_schema`, поэтому ответ идёт через `json_object`, схема текстом в системном сообщении, id проверяет `GuardedClassifier`). Промпт лежит файлом (ADR-005).
Классификатор вызывается из слоя навыка, `Resolver` о нём не знает (зависимость в одну сторону).

### 5. Отказ классификатора не блокирует запись
Таймаут, недоступность маршрута, невалидный ответ, `NONE`: трата записывается в «Прочее» с
заполненным описанием (как уже требует схема), в `category_review_queue` ставится запись для
разбора. Запись расхода от маршрута не зависит. Решение классификатора пишется в
`category_decision_log` (вход, выбор, источник), чтобы ошибки разбирались по факту.

### 6. Приватность
Владелец согласился отправлять **описания трат** бесплатным провайдерам через LiteLLM. В запрос
уходят описание и список имён категорий. Суммы, chat_id, имена людей из контекста диалога не
отправляются. Расширение набора полей требует нового решения владельца.

### 7. Конфигурация и модели
Существующие `LLM_CHAT_MODEL`, `LLM_FALLBACK_MODEL`, `LLM_TIMEOUT_SECONDS`, `VISION_*` **не
меняются**. Классификатору нужны отдельные новые параметры (маршрут, таймаут), с безопасными
значениями по умолчанию; их значения подтверждает владелец. Маршрут `standard` на прокси
существует (проверено 2026-10-21 по `GET /v1/models`, simpleAI-mg7v); для вызова нужен ключ прокси.

### 8. Правки соседних документов
- ADR-011, строка контекста: пример «(еда, кафе)» заменён на «(продукты, рестораны)».
  Правка текста внесена вместе с этим ADR.
- Эпик simpleAI-nebf: пометка «Не входит: классификатор, судья» закрыта ссылкой на этот ADR и
  эпик simpleAI-lsx5.
- `DefaultSynonyms`: записи «ресторан» и «кафе / ресторан» перестают вести на «Еда»
  (переназначаются в ADR-013 после появления «Рестораны»). Карта остаётся картой дублей, не
  классификатором.

### 9. Дубль номера 010
Было два файла с номером 010. Решение владельца 2026-10-21: фото чека переименован в
`014-receipt-photo-vision.md`; ссылки в коде, спеке и `deploy.yml` исправлены (simpleAI-38mn).
«ADR-010» теперь однозначно означает дедупликацию категорий.

## Отвергнутые варианты
- **Расширить хардкод-список до 12 имён.** Список снова расходится с БД при первой новой категории.
- **Классификатор внутри `Resolver`.** Resolver синхронный и детерминированный (ADR-010),
  сетевой вызов в нём ломает гонки создания и тесты.
- **Веб молча создаёт категорию.** Веб-форма с опечаткой плодит дубли, ради борьбы с которыми
  написан ADR-010.
- **Свободный ответ модели без enum.** Именно так появляются «Кафе / ресторан» и «Продукт».

## Последствия и риски
+ Бот и веб дают один результат на одно слово; промах виден, а не превращается в NULL.
+ Новая категория сразу доступна классификатору без правки кода.
− Веб-форма на неизвестную категорию теперь отказывает: фронту нужно показать ошибку и список.
− Бесплатные модели нестабильны по качеству: страхуют `enum`, журнал решений, очередь разбора.
− Описания трат покидают контур (§6): принято владельцем.
- Проверено на проде 2026-10-21 (simpleAI-mg7v): маршруты `standard`, `tools`, `vision` есть; 24 алиаса,
  дублей и очереди разбора нет.

## Тесты (обязательные требования)
- Каждый тест проверяется мутацией: сломать фикс и убедиться, что тест краснеет.
- Использование `Resolve` вебом проверяется спаем на **аргумент вызова**, а не подменой имени в
  модуле; мутация: вернуть `LOWER(name)` в одном из трёх мест.
- «Названная категория не идёт в классификатор»: спай на вызов классификатора, мутация: вызывать
  его всегда.
- Реальный вызов `standard` проверяется один раз вручную при выкатке, не только моком.
