# ADR-010: Фото чека — vision-вход через LiteLLM с подтверждением

- **Статус:** Proposed
- **Дата:** 2026-10-17
- **Контекст эпика:** simpleAI-7mc6 (issue #76)
- **Связано:** ADR-008 (конверты: предупреждение о пробитом конверте сохраняется). Номер 009 занят
  эпиком income-plan-sheet.
- **Внешняя зависимость:** маршрут `vision` в прокси litellm-free-models (эпик litellm-free-models-4,
  ADR-0001 §6 там).

## Контекст

Расход в бот сейчас вводится только текстом. Оператор хочет присылать фото чека: фото — просто
другой способ ввести те же данные. Telegram-адаптер уже кладёт фото во вложения `core.Update`,
но `HandleDefault` сохраняет его на диск и отвечает «обработка будет добавлена скоро».

Бот ходит в LLM напрямую (DeepSeek → Gemini с автоматическим fallback). Ни один из них не
отдаёт список возможностей моделей. Отдельный проект оператора, litellm-free-models, — прокси
LiteLLM над бесплатными провайдерами: маршрут — это цепочка моделей, запрос идёт дальше по
цепочке, когда у провайдера кончилась квота. `/model/info` прокси отдаёт `model_info.supports_vision`
и `supports_pdf_input` для каждого деплоймента.

Фото чеков — личные данные.

## Решение

### 1. Пайплайн строго по порядку

| Шаг | Что | При неудаче |
|---|---|---|
| 1 | Проверка файла: тип по сигнатуре, пересечение форматов, лимит размера | Отказ с причиной, модель не вызывается |
| 2 | Классификатор «чек / не чек» — короткий дешёвый вызов | «На фото не чек» / «не удалось проверить фото», шаг 3 не делается |
| 3 | Разбор чека vision-моделью через маршрут `vision` | Отказ с причиной, черновика нет |
| 4 | Черновик в памяти + кнопки «Записать / Отмена» | — |
| 5 | По нажатию «Записать» — расход через budget skill | Сообщение, расход не создан |

Каждый шаг выполняется только после успеха предыдущего. Подпись к фото игнорируется.

Вход в пайплайн — вложение-фото и вложение-документ. Telegram отдаёт чек либо сжатым фото, либо
файлом (несжатый JPEG, PDF). `Kind` и MIME от клиента используются только чтобы выбрать путь;
допуск решает шаг 1 по сигнатуре. Документ, чья сигнатура не входит в распознаваемые ботом,
идёт старым путём (сохранение вложения).

### 2. Форматы — пересечение, а не список в коде

Допустимые форматы = (что умеет группа моделей) ∩ (что бот умеет распознать по сигнатуре).

Флаги модели — да/нет, а не список форматов. Перевод флага в форматы фиксируется здесь:

| Флаг `/model/info` | Форматы |
|---|---|
| `supports_vision` | jpeg, png, webp, gif |
| `supports_pdf_input` | pdf |

Группа считается умеющей флаг, только если он `true` у **всех** её деплойментов: запрос может
уйти в любой из них. `None` считается как «нет».

Тип файла определяется только по сигнатуре содержимого. MIME и имя от клиента игнорируются.
Лимит размера проверяется по реально прочитанным байтам.

### 3. Классификатор — отдельный шаг за своим портом

Отдельный порт `Classifier`, чтобы реализацию можно было заменить (например, локальной моделью)
без правки сценария. Текущая реализация — тот же маршрут `vision`, но дёшево: картинка уменьшена
до ≤512 px по длинной стороне, `max_tokens` ≈ 10, `temperature` 0, ответ ровно
`{"is_receipt": true|false}`. Любой другой ответ — отказ, основной вызов не делается.

Разбор (шаг 3) тоже возвращает `is_receipt` — вторая страховка от ложного «да», бесплатно.
Черновик создаётся только при `is_receipt`, сумме > 0 и ISO-валюте. Без валюты — отказ: иначе
запись молча получит RUB.

Цена: у бесплатных провайдеров дефицитны запросы в день, а не токены; два запроса на фото для
личного бота приемлемы.

### 4. Модели и fallback

Бот вызывает одну модель — маршрут прокси `vision` (`VISION_MODEL`). Выбор и порядок моделей
внутри цепочки — дело прокси. Fallback только внутри цепочки `vision`: vision-вызов идёт мимо
составного клиента DeepSeek → Gemini, картинка никогда не уходит модели без vision.

Конфиг — отдельные ключи `VISION_LLM_BASE_URL`, `VISION_LLM_API_KEY`, `VISION_MODEL`. Существующие
ключи не меняются. Ключи не заданы или прокси недоступен → бот стартует, на фото отвечает
«обработка фото не настроена». Каталог моделей перечитывается по TTL: прокси, поднятый после
старта бота, подхватывается без рестарта. Прод-конфиг этим ADR не меняется.

### 5. Подтверждение: черновик в памяти, запись через skill

- Черновик хранит только разобранные поля, без байтов картинки.
- Привязан к чату, живёт по TTL, `Take` атомарен: двойное нажатие даёт один расход. Нажатие из
  чужого чата — отказ. После рестарта черновики теряются — допустимо.
- Данные кнопки — только префикс `rcpt:` и id черновика (Telegram ограничивает их 64 байтами).
- Запись — `registry.Get("budget").Run(add_expense)`, тот же путь, которым агент вызывает навык,
  но без LLM: подтверждённые цифры не пересказываются моделью. `skills/budget` не меняется,
  предупреждение ADR-008 сохраняется.

### 6. Приватность

Фото не хранится нигде: ни на диске (ветка для фото стоит до сохранения вложений), ни в
черновике, ни в логах. Байты, base64 и распознанный текст не логируются. Маскировка на стороне
прокси (Langfuse, spend logs, кэш) — в эпике litellm-free-models-4.

### 7. Границы модулей

Зависимости направлены внутрь, к домену.

| Слой | Пакет | Что | Импортирует |
|---|---|---|---|
| Порты | `internal/core/vision.go` | `VisionLLM`, `ModelCatalog` | stdlib |
| Сценарий | `internal/receipt` | `filecheck`, порты `Classifier` / `Parser` / `DraftStore` / `ExpenseWriter`, `Service` (шаги 1–4) | `core`, stdlib |
| Адаптеры | `adapters/llm/litellm` | `ModelCatalog` над `/model/info` | `core` |
| | `adapters/llm/openai/vision.go` | `VisionLLM`: картинка как data-URL | `core`, openai-go |
| | `receipt/memdraft` | `DraftStore` в памяти | `receipt` |
| | `ExpenseWriter` над `plugin.Skill` | шаг 5 | `receipt`, `plugin` |
| Вход | `telegram/receipt_handler.go` | ветка фото, callback `rcpt:` | `receipt` |

`internal/receipt` не импортирует telegram, budget и openai.

## Последствия

- Фото и документы-чеки (распознанная сигнатура) перестают сохраняться в `MediaDir` и попадать
  в ingest-JSON. Голос, аудио и прочие документы работают как раньше.
- До прода нужны деплой прокси (litellm-free-models-1.5) и решение оператора о ключах `VISION_*`
  в `deploy.yml`.
- Повторная отправка того же чека создаст второй черновик. Защита по `file_unique_id` требует
  правки адаптера Telegram и отложена.

## Отвергнуто

- **Один вызов модели вместо отдельного классификатора** — дешевле, но оператор хочет отсечь
  не-чек до основного разбора; порт оставляет возможность удешевить шаг позже.
- **Список моделей в конфиге бота** — дублирует прокси, который уже знает возможности моделей.
- **Отправить подтверждённый разбор агенту текстом** — LLM может изменить цифры между
  подтверждением и записью.
- **Состояние черновика в данных кнопки** — не помещается в 64 байта.
